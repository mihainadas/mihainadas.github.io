# Blog working agreements

Before planning, researching, drafting, or editing this repository, read:

1. `docs/publishing-policy.md`: the standing editorial, publishing, visual, media, language, research, and referral rules.
2. `README.md`: exact authoring conventions, mathematics, translation checks, figures, and site mechanics.
3. For books or shop links, `docs/books-operations.md`; for decorative assets or typography, `assets/editorial/README.md`.
4. For reusable media, `assets/media/README.md`; for business positioning, career data, or the résumé, `docs/professional-operations.md`.

Apply these rules to every manual and scheduled update. Do not rely on chat history or a historical automation-memory entry in place of the current files. A policy reference is not permission to broaden the current task, change a schedule, weaken a check, or submit an account, agreement, tax, banking, or payment action.

Preserve user changes. Scheduled publishing starts only from a clean tree after the precise collision-copy recovery gate in the publishing policy. Keep the one-post-per-run and three-posts-per-Europe/Bucharest-week limits.

Do not manufacture a review, reading experience, experiment, result, translation approval, or review date. If evidence or authorization is missing, report the specific gap instead of silently lowering a gate.

When the user changes a standing rule, update the canonical policy and any affected operational guidance together. Keep mutable account status and dated run outcomes in scheduler memory, not in these standing rules. Do not change standing policy during a normal scheduled publishing run without explicit user authorization.
